## Change 1 — LEDGER templates (E1+E2+D3)
- Added a **`Kind`** column to the Frontier table (both repos), default `authoring`;
  values authoring/ui/eval/deploy-infra/data/diagnosis, each documented in
  Conventions with its verified-done audit dimension. Example rows show a
  multi-file `authoring` unit and a `ui` unit.
- Output-cell contract (D1/D2): **concrete backticked path(s) only** — no
  globs/dirs (a dir would over-freeze every file under it; a glob realpaths to a
  literal matching nothing), **multi-file = comma-separated backticks**
  (`` `a.ts`, `b.ts` ``), **no raw `|`** (shifts columns; hook fails safe).
- Machine-parse convention updated: hook reads by column NAME, parses ALL
  backticked paths, fails safe on a mis-split row.
- Plugin template uses `.gotm/…` store paths; framework uses generic paths. Both
  otherwise consistent.

## Change 2 — hook `gotm-immutability.py` (E1/D1)
- (a) **Parse ALL backticked Output paths** — `_strip_output` now `re.findall`s
  every `` `…` `` span (was `re.search` → first only); `_record` iterates them, so
  a unit freezes/activates *every* owned path.
- (b) **Fail safe on a malformed row** — `_header_cols` records the header column
  count; `_parse_table_line` skips any `| U.. |` row whose cell count ≠ the header
  count (a stray `|` shifted the columns), freezing/activating nothing for it and
  writing a stderr note — never trusting a shifted Output index. Other rows still
  parse.
- Kept: v3 states (authored/verified/done→frozen; pending/in_progress→active;
  superseded→neither), Frontier + Archive-bullet + LEDGER-ARCHIVE parsing,
  follow-on ownership override, fail-open on exceptions, deny-via-stdout.

## Change 3 — compaction `compact_ledger.py` (E5/B1)
- `LEDGER-ARCHIVE.md` sibling now **appends** (dated `## Compaction run <date>`
  block per run) instead of overwriting, and is **backed up first** to
  `<archive>.bak` (mirrors the ledger `.bak`). The pre-existing in-ledger
  `## Archive` bullet merge is untouched (still merges + de-dupes newest-first).

### Multi-file ownership (D1/A2)

Ledger U1 = `verified-done`, Output `` `src/a.ts`, `src/b.ts` ``;
U2 = `in_progress` follow-on, Output `` `src/foll_a.ts`, `src/foll_b.ts` ``.

```
done multi-file: edit a.ts        => DENY   (both files of a closed unit owned)
done multi-file: edit b.ts        => DENY
in_progress follow-on: edit foll_a => ALLOW  (active unit owns → editable)
in_progress follow-on: edit foll_b => ALLOW
```

Overlap case — a follow-on re-owns BOTH already-frozen paths of a closed unit
(U1 verified-done `x,y`; U2 in_progress `x,y`):

```
shared_x.ts => ALLOW (follow-on owns it)
shared_y.ts => ALLOW (follow-on owns it)
```

Before the fix only the FIRST path was owned, so `b.ts` / the 2nd shared file
would have wrongly denied (A2's exact bug).


the malformed row corrupt the parse of the other rows.
