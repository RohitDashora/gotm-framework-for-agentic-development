### LOW severity

- **L1 — The Index instruction is thinner than the template's defined Index format; a producer following only the prompt may emit an under-specified index line.** `prompts/outcome-analysis.md:45` instructs: "generate the **Index** at the top of `LEARNINGS.md` — one tag-prefixed line per record. The index is what future projects scan; the records are what an aggregation layer ingests." The template, however, pins an exact index line format at `templates/LEARNINGS.md.template:9`: `` `L#  [tags]  claim → fix-gist.  (kind · confidence · source)` ``. The prompt names the index, its purpose, and its tag-prefix, but does not restate the `→ fix-gist. (kind · confidence · source)` shape, and unlike the record block (which is reproduced inline) the index format is left implicit-by-reference. Because line 32 already routes the producer to "per `templates/LEARNINGS.md.template`" for the record and line 53 names the template again for the whole file, a careful producer will pick the format up from the template; but a producer working from the prompt alone could emit a looser index line. Cosmetic completeness gap, not a contradiction with the template. Fix if convenient: add the one-line index format string (or a back-reference "use the index line format defined in the template") at `prompts/outcome-analysis.md:45`.

- **L2 — The emitted record block omits the inline `confidence` ladder hint the template carries, relying on prose two paragraphs later.** The template's record block annotates `confidence: candidate   # candidate (1 project) → validated (≥2 independent) → core` (`templates/LEARNINGS.md.template:30`). The prompt's reproduced block shows only `confidence: candidate` with no inline comment (`prompts/outcome-analysis.md:43`). The ladder is fully and correctly stated in the prose immediately below (the "Confidence — be honest about n = 1" section, `:47-49`), so there is no information loss and no drift — this is a presentational nit only. The prompt's block also omits the `kind` enumeration comment that the template carries inline (`# gotcha | prerequisite | pivot | pattern | anti-pattern`, template `:24`), but the prompt supplies the 5 kinds inline in the `<...>` placeholder (`kind: <gotcha|prerequisite|pivot|pattern|anti-pattern>`, `:37`) AND enumerates them with definitions in the Classify step (`:26`), so that omission is fully compensated. No action required.
