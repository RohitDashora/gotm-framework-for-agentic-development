# GOTM v3.1 — enhancement design (from knowledge-graph v3 field feedback)

> **Status:** v0.1, for redline. The foundation doc for the v3.1 enhancement — the same role `V3-DESIGN.md` played for v3.
> **Source:** the 2026-07-01 batch in `knowledge-graph/.gotm/FEEDBACK.md` — a real project running GOTM **v3** in production (a Databricks context-graph + live App). These are the first findings from *running* v3, not from designing it.
> **Method:** evaluate each finding to root cause → re-derive GOTM from first principles → plan the enhancement at the root, not the symptom. On disk, not chat (GOTM's own rule).

---

## 1. Per-finding evaluation (understand each)

Each: **what happened · mechanism (why) · what it reveals · fix verdict**.

### A1 — glob/directory Output cells false-block sanctioned follow-on edits (bit U111, U123, U117-B)
- **What:** the immutability hook denied *legitimate* follow-on edits to frozen files; workers had to Bash-bypass (bad) or refuse (good).
- **Mechanism:** the hook grants the follow-on exemption only if an `in_progress` unit's Output cell *exact-realpath-matches* the file. Owning units used dir/brace-globs (`pipelines/…`, `{server,client}/src`), which realpath to a literal that matches no concrete file → the path never enters the `active` set.
- **Reveals:** the Output cell does double duty — a human's convenient shorthand ("the pipelines dir") **and** the machine's ownership key. Shorthand silently breaks the key.
- **Verdict:** convention (concrete paths) is correct and immediate. The proposed glob/subtree *matching* is **wrong** — a dir Output would freeze every file under it (incl. untracked/new) and over-grant ownership. Forbid globs in Output cells; list concrete paths. → **P1.**

### A2 — multi-file Output: only the *first* backticked path is owned (bit U145)
- **What:** a unit with Output `` `a`, `b` `` owned only `a`; an edit to `b` (a closed unit's tracked output) was hard-denied. Earlier multi-file units escaped only because their 2nd files were *untracked* (silent).
- **Mechanism:** `_strip_output` uses `re.search` — first backtick only.
- **Reveals:** the parser bakes in "a unit owns one output," but units legitimately own several files (a module + its test; a component + its types). Atomicity ("one deliverable") ≠ one *file*.
- **Verdict:** the fix (parse **all** backticks) is correct, minimal, and completes ownership in both directions. **But it edits the enforcement guardrail — needs explicit user sign-off** (KG's auto-mode correctly refused to self-widen; that posture is right). → **P1.**

### A3 — a literal `|` in a cell breaks the table parser (bit U123)
- **What:** U123 stayed blocked *even with* a concrete Output path, because its description held `[dimension | Graph | Plain RAG]`; the pipes shifted columns so Output was read at the wrong index.
- **Mechanism:** the hook splits rows on `|`; Markdown has no escaping story a naive positional parser respects.
- **Reveals:** the machine-index lives in a format whose delimiter can appear in the human content — fragile by construction.
- **Verdict:** convention (no raw `|`) right; the durable fix is (a) the **G18 ledger-parse lint rejects a mis-splitting row at write time**, and (b) the hook **fails safe** on a malformed row (don't trust a wrong-column Output; surface it). → **P1.**

### B1 — `compact_ledger.py` not cumulative across runs → data loss
- **What:** a 2nd compaction's own self-check FAILED (`MISSING: U1..U76`).
- **Mechanism (KG's old copy):** rebuilds `## Archive` from only this run's spill (drops prior bullets); overwrites `LEDGER-ARCHIVE.md`; backs up only the ledger, not the archive.
- **Reveals:** compaction was written as one-shot, and the "nothing is deleted" invariant was never tested across runs.
- **Verdict:** **v3.0.0 already fixed the critical half** (verified — it merges pre-existing `## Archive` bullets). Residual: make the `LEDGER-ARCHIVE.md` sibling append + back up. LOW (bullets carry the lossless index). A robustness/idempotence gap, not one of the deep patterns.

### C1 — SEV1: a destructive `bundle deploy` DELETED the live app
- **What:** removing the app from `databricks.yml` + `bundle deploy` destroyed the live app (it was in the bundle's Terraform state). Full outage; caught by the human.
- **Mechanism:** `bundle deploy` reconciles config→state; remove-from-config + apply = destroy. No dry-run/plan review; the plan literally prints "destroy app."
- **Reveals:** **every GOTM gate is post-hoc** (audit *after* authored-done). A destructive op is irreversible — there is nothing to audit after; the app is already gone. GOTM has **no pre-execution gate**. ("Remove from IaC + apply = delete" is a domain trap a plan-review catches generically.)
- **Verdict:** KG's "destructive-op gate" is the right direction but landed as a *rule* (vigilance). It must be a **mechanism**: irreversible ops require an independent dry-run/plan review *before* execution. Highest priority — it deleted a live app and it's a **recurrence** of the 2026-06-23 deploy-rigor finding. → **P3.**

### C2 — driver context bloat (context-economy drift)
- **What:** the driver held v3's structure but let verbose worker *return bodies* flow in and inlined them into over-long ledger cells.
- **Mechanism:** dispatches asked for "terse" but didn't *force* detail-to-disk; workers returned long reports; the driver absorbed them.
- **Reveals:** v3's headline invariant (context economy) is enforced **nowhere** — it rides on the driver choosing not to hoard and the worker choosing to be terse.
- **Verdict:** the fix (force detail-to-disk; hard return cap; cells = pointer) is right and must be **mechanical** — the dispatch contract mandates it; over-cap returns are a defect. → **P4.**

### C3 — units marked DISPATCHED without launching the worker
- **What:** `in_progress`/"DISPATCHED" rows were written but no Agent call was made; nothing ran; the human caught it.
- **Mechanism:** amid interleaved messages, the ledger stamp decoupled from the actual dispatch.
- **Reveals:** the ledger records **intent**; a status can be written without its action having happened — the source-of-truth can lie.
- **Verdict:** the fix (stamp DISPATCHED only *after* the Agent call returns an id — the id is proof; turn-end rescan) is right and small. → **P5.**

### D1 — UI `verified-done` on a stale build + unreliable worker prose
- **What:** a UI unit churned ~6 iterations; two "failures" were a *stale served bundle*; workers reported "renders fine" the screenshots contradicted.
- **Mechanism:** verified-done didn't ensure the audited artifact was a build of *current* source, and leaned on worker prose about visuals.
- **Reveals:** for UI units, verified-done has two failure modes the generic check misses — **staleness** (audited the wrong build) and **subjective prose** (unreliable on visuals).
- **Verdict:** right → a **UI-kind** audit dimension: rebuild from current source; objective machine checks (DOM/bbox/counts); driver views firsthand. → **P2.**

### D2 — measurement/judge harness rigged (the demo's headline comparison)
- **What:** the LLM-judge systematically penalized the graph arm (`EVIDENCE_CAP=8 < SYNTHESIS_K=12` → cited-but-unshown segments flagged "fabricated"; + position bias; + one arm titles-only). Retrieval was fine; the *measurement* was rigged.
- **Mechanism:** verified-done for an eval unit checked "runs + emits a number," not "is the yardstick fair."
- **Reveals:** for units whose *purpose* is to measure/compare, correctness **is** harness fairness. A biased harness yields confident-wrong conclusions the whole project leans on — the single most dangerous silent failure.
- **Verdict:** right, and the **highest-value new dimension** → an **eval/judge-kind** audit dimension: equal-fidelity inputs both sides, symmetric yardstick, position/order bias via A/B swap, confounds controlled or labelled. → **P2.**

### D3 — acted on a confounded "X underperforms" signal
- **What:** "Plain RAG wins" was read as "graph retrieval is bad"; actually two confounds (graph on a weaker model; the D2 judge bug). Nearly fixed the wrong thing.
- **Mechanism:** root-caused a component from a confounded signal without controlled reproduction.
- **Reveals:** diagnosis units (spawned from "X is broken") need a controlled-reproduction step *first*.
- **Verdict:** right → a **diagnosis-kind** rule: reproduce under controlled conditions (strip model/harness/config confounds) before root-causing. → **P2.**

### D4 — identity-bound infra "recovered" but every query failed
- **What:** recreating the app minted a NEW service principal; grants were bound to the OLD SP → app ran but every query failed (`relation does not exist` — looked like data loss, was a permission gap). Compounded by a pipeline hardcoding the old SP.
- **Mechanism:** verified-done checked "app is RUNNING," not "works AS the deployed identity end-to-end."
- **Reveals:** for stateful, identity-scoped infra, "recreate" ≠ "recover"; and hardcoded identity defaults are a fragile binding that breaks on recreation.
- **Verdict:** right → a **deploy/infra-kind** dimension (exercise end-to-end as the deployed identity) + hardcoded identity/endpoint = an **enforcement (check-6) finding**. → **P2.**

## 2. GOTM from first principles — the 11 symptoms are 5 structural gaps

- **P1 — The ledger conflates a human narrative with a machine-authoritative index.** A1/A2/A3 (+ the earlier G18) are one thing: the hook / compaction / converter must reverse-engineer *(unit → owned paths, status, verdict)* out of a hand-edited Markdown table with free prose in cells. Positional parsing of a free-form doc is fragile by construction and will keep breaking.
- **P2 — `verified-done` is under-typed.** D1–D4 aren't four additions; they're evidence that "exercise the live artifact" means something *different* per unit **kind** (UI ≠ eval ≠ deploy ≠ data ≠ diagnosis), and GOTM ships one generic check for exactly the units where "looks done ≠ is done" is widest (measurement above all).
- **P3 — There is no *pre-execution* gate for irreversible actions.** Every GOTM gate is post-hoc (audit after authored-done). You cannot audit away a deleted app. Destructive ops need a gate *before* execution — structurally absent.
- **P4 — Context economy is aspirational, not enforced.** v3's headline invariant relies on the driver choosing not to absorb worker bodies. Nothing stops it.
- **P5 — The ledger records intent, not verified fact** (DISPATCHED drift). Minor but real: the source-of-truth can diverge from reality.

### The meta-finding (the organizing insight)
GOTM's founding thesis: *memory-based discipline is exactly what GOTM distrusts — materialize it as a mechanism.* v3 did that for **authoring** (the DAG topology) and **auditing** (structural independence + the freeze hook). But **P1, P3, and P4 are precisely the disciplines v3 left as agent vigilance — and those are the three that broke in the field.** So the enhancement is not new philosophy; it is **finishing the application of v3's own philosophy to v3's own gaps.** P2 is the exception — not discipline-vs-mechanism, but under-specification (verified-done needs to be typed by unit kind).

A second-order note: P1 and P3 share a smell — GOTM trusts a *free-form* representation (a prose ledger cell; an operator's memory of "which command is safe") where it needs a *typed, validated* one. The through-line of v3.1 is **typing and validating the load-bearing surfaces** (the Output cell; the verified-done check; the pre-execution gate; the worker return).

## 3. The enhancement plan (v3.1)

Each **E** targets a root **P**, prefers a *mechanism* over a rule, and states framework-vs-plugin split + sign-off needs.

### E1 — Ledger as a validated micro-schema (P1 → A1/A2/A3, G18)
- **Contract:** Output cells hold **concrete backticked path(s)** — no globs/dirs; multi-file = comma-separated backticks; no raw `|` (use `/` · escape).
- **Mechanism:** the **ledger-parse lint** runs at session-start reconcile *and* on every driver write — a row that mis-splits, has an invalid status, or an unparseable Output is rejected *before* it can mislead the hook. The hook parses **all** backticked paths and **fails safe** on a malformed row.
- **Framework:** PROTOCOL (Output-cell contract + the lint), LEDGER template (Conventions). **Plugin:** hook (all-backticks + fail-safe — **A2 sign-off**), the lint surfaced in `/gotm:what` + session-start.

### E2 — Typed `verified-done`: kind-specific audit dimensions (P2 → D1–D4)
- A unit declares a **kind**; the audit adds dimensions atop the 7-point:
  - **UI/visual** → artifact-freshness (rebuild from current source) + objective machine checks + driver firsthand view.
  - **eval/judge/measurement** → harness-fairness (equal-fidelity inputs, symmetric yardstick, A/B-swap for position bias, confounds controlled/labelled).
  - **deploy/infra** → exercise end-to-end *as the deployed identity*; hardcoded identity = enforcement finding.
  - **data** → re-query the target as the downstream consumer.
  - **diagnosis** → reproduce under controlled conditions (strip confounds) before root-causing.
- **Framework:** `prompts/audit.md` + PROTOCOL Audit gates (a kind→dimensions table) + ch6. **Plugin:** mirror + `/gotm:audit` picks the kind.

### E3 — Destructive-op pre-execution gate (P3 → C1, the SEV1; top priority)
- **New gate class (pre-hoc):** before a worker runs an irreversible op (a destroying deploy, `DROP`, delete, `terraform/bundle` apply, unbind/rebind), the driver requires a **dry-run/plan produced and reviewed by an independent context first**. Gate *before*, don't verify *after*.
- Rule baked in: "remove-from-IaC + apply = DELETE; decouple with `unbind`, never delete-from-config."
- **Framework:** PROTOCOL new "Destructive-op gate" section + the loop (driver demands the plan before dispatching the destructive worker). **Plugin:** mirror + bootstrap note. (Optional later: a `PreToolUse` hook that flags destructive Bash commands — a sibling to the immutability hook.)

### E4 — Forced detail-to-disk dispatch (P4 → C2; makes economy mechanical)
- The dispatch contract **mandates**: the worker writes full detail to its output/report file and **returns ≤ N lines** (pointer + verdict + blocker). The driver records the pointer, never the body; ledger cells = summary + pointer; merges are fan-in workers. Over-cap returns are treated as a defect.
- **Framework:** `prompts/worker-dispatch.md` + PROTOCOL (worker contract) + ch5 (economy). **Plugin:** mirror.

### E5 — Proof-stamped dispatch + compaction sibling backup (P5 + B1; cleanup)
- DISPATCHED is stamped only with the launched agentId (proof); turn-end reconcile that no in_progress/DISPATCHED row lacks a real Agent call.
- `compact_ledger.py`: append to (not overwrite) `LEDGER-ARCHIVE.md` and back it up first.
- **Framework:** `prompts/driver-loop.md` + PROTOCOL. **Plugin:** driver-loop + `compact_ledger.py`.

### Sequencing & delivery
1. **E3** (prevents deleting live resources) and **E1** (actively impeding real work) first.
2. **E2** (richest correctness value — esp. eval harness-fairness).
3. **E4**, then **E5**.
Framework-first, then the plugin mirror. Built **driver/worker** and **independently audited** (the same discipline the build audit used — and this time run through the gated ledger, closing that process gap too).

## 4. Decisions (LOCKED — 2026-07-08, user approved the recommendations)
- **D1 — A2 guardrail change: APPROVED.** The immutability hook parses **all** backticked Output paths (frozen + active), and **fails safe** on a malformed row (wrong column count / unparseable Output → do NOT trust the Output index; treat conservatively and surface, never silently mis-freeze).
- **D2 — glob policy: FORBID.** Output cells hold **concrete backticked path(s) only** — globs/directories are rejected by the ledger-parse lint. (No hook glob-matching: a directory Output would over-freeze every file under it, incl. new ones.)
- **D3 — kind: an explicit `Kind` column** in the ledger, default `authoring`. Kinds: `authoring` · `ui` · `eval` · `deploy-infra` · `data` · `diagnosis`. The audit reads it to pick verified-done dimensions.
- **D4 — destructive-op list (initial, extensible):** any deploy/apply that can destroy or replace a live resource (`databricks bundle deploy`, `terraform apply`), `DROP`, resource `delete`, bundle `unbind`/`rebind`, grant `REVOKE`, `git push --force`, and any irreversible data mutation (truncate / purge / overwrite-in-place). These trip E3's pre-execution plan-review gate.
- **D5 — version: v3.35** (`plugin.json` + `marketplace.json` → `3.35.0`).
